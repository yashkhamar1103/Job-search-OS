# review/

Generated files for Yash to read. Nothing here is an input to a run.

## `confirmed_aliases.md`

Generated by `python -m app.cli.confirmed_aliases`, from `vocab/taxonomy.json`
and `evidence/ledger.json`.

Reviewing the whole taxonomy is not a useful task: it has hundreds of entries,
most of them technologies Yash does not have. What matters is narrower. For the
technologies the ledger actually confirms, which strings will be read as naming
them? Every alias in this file is a phrase that may appear in a CV, so a wrong
alias under a confirmed id is a fabrication with a clean bill of health.

This is the file to review. The taxonomy is reference data.

It does not exist until `evidence/ledger.json` does. CI regenerates it and fails
if the committed copy is stale.

## `taxonomy_candidates.json`

Written by a run (milestone 2) when a job description contains a term the
taxonomy does not know. For Yash to triage by hand.

Nothing in the app writes a candidate into `vocab/taxonomy.json` or into
`evidence/ledger.json`. The triage is manual on purpose: a posting asking for a
technology is not evidence of having used it, and that is precisely the
direction the original fabrication travelled.
